**真机液态计分。** Mac 本地读取合成英文，既有 Linux CPU 上的冻结 LTC 接收数值路径；同一权重、相同 worker 源码和摘要，无新训练。32 场中有 18 种完整数值路径。单份文档计分从 2.592 秒到 2.406 秒，约 1.08×（各 3 次中位数，含 SSH、进程启动、往返与本地结果生成；不含输入输出文件写盘）。改为 4 份文档、每份 8 场，在新版逐份计分需 9.084 秒，一次合批 2.447 秒，**3.71×**。这是摊薄远端开销与复用同一路径的合计收益；不是称神经网络层本身快了 3.71 倍。合批仍允许不同文档出现相同作者和发言 ID，因为分数、条件统计、配对及原文地址分别生成。

## 实现改变了哪一步

- **文本入口。** 一次载入冻结词表、IDF、SVD、节点参数；每批最多处理 512 个切片，随后按原来的会话和发言顺序放回。硬树按同一节点上的多行算到各子中心的距离；距离并列仍取首个子节点。未知词表通道和独立会话边界保留。
- **因子发现。** 观察数据仍求完整特征向量；置换仅提供特征值阈值，无须求方向。使用对称矩阵特征值例程；可能因浮点尾差改变严格大于判定的候选，按原种子与原算法复核整个置换阈值。阈值之外的谱值允许正常的浮点误差。
- **来源追踪。** 将源节点权重与逐片撤去效应的缩并改写为一次双精度矩阵乘法，保留各目的节点与时间位置，而不是只求总效应。完整的逐片撤去仍需二次规模输出，未抽样删减。此处使用本机 BLAS，而不是自行编写特定 CPU 指令。[NumPy 的运行时指令分派](https://numpy.org/doc/stable/reference/simd/index.html)。
- **液态前向。** 同一冻结权重下，每场独立重置的输入如果形状与数值字节完全相同，只做一次计分，再按原顺序复制到观察位置。没有近似近邻匹配，也不缓存到下一次研究。训练保留所有重复样本；合批只适用于冻结计分。
- **双视角。** 约束矩阵每条转移只触及相邻两个状态，用稀疏表示。需要整段上下界的调用仍返回各时点上下界；只问末时点时求两个线性目标而非 2T 个，过去的观察与约束一条也没有移除。阈值、可行性和简单滞后比较规则不变。[SciPy HiGHS 求解器说明](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs.html)。

## 哪些工作给 GPU

**回归测试状态。** 本轮涉及的节点、因子、液态、双视角、手册和原生计分测试共 118 项通过。另在无私有数据的干净检出尝试全仓测试，17 个历史测试模块在收集阶段找不到未分发的 `results/grain_gptpro_foundation_v3` 产物；未改动的基线也缺相同的 17 个模块所需产物。没有把它们跳过后当作全仓通过。

在 M4 上用真实 Metal/MPS 设备测试同一来源归因矩阵乘法，输入从 CPU float64 转至设备 float32，计算后取回 CPU（包含同步）。大小为“机会数 × 节点数”。CPU 与 GPU 的时间均为 7 次中位数，单位毫秒。

| 大小 | CPU float64 | MPS float32 含往返 | 最大绝对数值差 |
|---|---:|---:|---:|
| 24 × 8 | 0.00125 | 0.460 | 3.7e-9 以下 |
| 128 × 32 | 0.0945 | 0.638 | 1.1e-8 以下 |
| 128 × 64 | 0.417 | 0.848 | 5.3e-9 以下 |

对这些由 CPU 提供数据的小矩阵，直接用 CPU。此实验没有测大模型编码、GPU 常驻的大批张量、CUDA 或完整 LTC 的 GPU 吞吐，故不替这些负载作决定。在具备设备的其他部署可用下方命令重新测量；GPU 非安装依赖。下一项有决策价值的 GPU 测试是：让输入编码、批量前向、归因运算保持在同一设备上，再量整份报告的耗时和科学输出，而不是只量一个不同精度的核函数。

## 集成版：开放语流和混合数据

同机固定输入上，稀疏缺席索引处理 2,400 和 24,000 条事件分别加速 1.44 倍与 3.57 倍，最大数值差为 0。使用已有论坛计数、作文和按键资料准备相同的 21,417 条观测与 10,800 条机会，整包 JSON 约 89 ms / 77 MiB，逐行索引约 123 ms / 52 MiB，分析输出相同。后者减少解析峰值，仍需保留内存索引。见[缺席算子基准](../reports/evidence_panel_benchmark.json)、[输入与查询基准](../reports/evidence_real_replay.json)和[选择输入格式](GRAIN_EVIDENCE_PANEL.md)。

## 使用

常规单份 `fit`、`score`、`dual_view_increment` 及教学命令不变。批量冷计分时，输入 JSON 为 `{"documents":[<原 score 文档>, <原 score 文档>]}`，输出 `results[i]` 等同于对第 i 份调用普通 score。各文档不共享读者状态，也不合并同批标准化。上限为 16 份，同时检查轨迹展开规模；超过预算时拆成几批，单份过大则按既有单份接口使用。不会自动移走数据；选择 SSH 时沿用液态工具手册中的数值 worker 配置。

```sh
python -m grain_core.liquid_instrument score-batch --input documents.json --reference ref.json --out scores.json
VECLIB_MAXIMUM_THREADS=1 python -m examples.benchmark_pipeline --repeat 7
VECLIB_MAXIMUM_THREADS=1 python -m examples.benchmark_pipeline --repeat 7 --gpu-probe
python -m examples.benchmark_pipeline --liquid-reference whole_ref.json --transport ssh --repeat 3 --batch-docs 4
```

若需重做前后对照，在另一干净目录检出基线，从**各自目录**用同一解释器运行新版基准脚本，例如 `python -c 'import runpy; runpy.run_path("/absolute/path/to/examples/benchmark_pipeline.py", run_name="__main__")' --repeat 7`。这样导入的是当前目录里的库，且不必修改旧版本。合批入口仅在新版存在。脚本输出每次计时而不只给最快一次。[原生工具总手册](GRAIN_USER_MANUAL_ZH.md) · [冻结阅读器与远端环境](GRAIN_LIQUID_TOOL.md)。

**复核。** 教学样例新旧九份产物逐字节一致；冻结 LTC 的 32 场合成材料完整 JSON 也逐字节一致；真机合批的四份完整结果与四次分开的结果相等。回归测试另以独立稠密 LP 检查稀疏全路径及末点、以单行路径检查批切边界/OOV、以旧特征值算法检查置换和严格相等门槛。不将“这几个输入逐字节相同”推广成不同 BLAS/平台一律逐字节相同。
