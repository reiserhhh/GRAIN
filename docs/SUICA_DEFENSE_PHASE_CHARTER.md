## Why a defense phase, and what it defends

The theory phase produced claims whose value depends on their
tamper-evidence and on honest exposure to adversarial checks that the
open-exploration phase deliberately deferred:

1. **Prospective seal #2 (time lockbox).** OP-31 sealed once before V8;
   the V8+IDT stack has since accumulated 60+ commits of registered
   claims. A second prospective seal — registered predictions with salted
   hashes, opened on a future date — is the cheapest high-value defense.
2. **Independent adversarial verification pass.** Standing rule 8 and the
   G-cite gates verify facts the PLANNER cites; no independent agent has
   yet been tasked to REFUTE the K-line's headline numbers from artifacts
   alone (the V8-era audit pattern, applied to M4-K). One leg: a
   refutation-tasked agent per headline claim, majority-refute kills.
3. **Lockbox / release engineering.** The release CI verifies the sealed
   v0.2.1 tag; the K-line's results live in gitignored `results/` with
   hashes only in reports. A defense leg specifies which artifacts get
   content-addressed archives so that every number cited in
   IDT/appendices is reproducible from a sealed bundle.
4. **The deanonymization ethics note, operationalized.** IDT §8 states
   the risk (T6/T3: residual patterns re-identify without content). The
   defense phase owes a written governance rule for any future real-text
   work: what the program will and will not compute on human text, and
   which readings require the frame-refreshed discriminator so forged
   identities are not reported as persons.
5. **Robustness of the standing-rule machine itself.** Rules 9–17 were
   born from defects; a defense leg replays a sample of closed legs
   against the CURRENT rule set (would today's gates have caught
   yesterday's defects earlier?) — measuring the machine, not the world.

## Boundaries

Defense work licenses no new theory claims; it can only strengthen,
qualify, or kill existing ones. Tier statements and the claims ledger
continue to control. Nothing in this phase touches frozen operators; the
two certified-unadopted repairs stay unadopted unless the program owner
decides otherwise under F16.
