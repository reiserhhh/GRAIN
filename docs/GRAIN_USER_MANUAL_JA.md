# GRAIN 総合利用手引き：発話の収集から個人差の推定まで

[English](GRAIN_USER_MANUAL.md) · [简体中文](GRAIN_USER_MANUAL_ZH.md) · 日本語

[現行ツール一覧、入力仕様、オフライン確認手順](GRAIN_CURRENT_TOOLCHAIN.md)

普段の行動頻度と、同じ機会が与えられた場合の応答を区別するには、[条件別応答の測定手順と会話データによる検証](GRAIN_RESPONSE_PROFILE.md)を参照してください。

参加者の入れ替わり、不規則な投稿、抽出前後で重複する標本を扱う場合は、[時系列分析の追加手法と計算例](GRAIN_OPEN_STREAM_OPERATORS_G1_G6.md)を参照。

「別案をよく出す人か」と「前提を訂正されたときに案を練り直す人か」は、同じ議事録から調べられる別の問いである。前者には発言機会の分母が要る。後者には、誰が誰を訂正し、そのあと本人に発言の機会があり、何と答えたかが要る。本書では、まず同一の発言を使った小さな研究を動かし、次に手元の資料で参照集団と観測法を作る。最近追加された二視点分析は、必要な問いを扱う際にだけ使う。

## 1. 最初に決めるのは出力の単位

| 知りたいこと | 残す単位 | 渡すもの |
|---|---|---|
| 新しい書き手は集団のどこに位置するか | 独立した書き手につき一行 | 各軸の百分位と多変量での中心からの距離 |
| どこに参加し、そこでどう表現するか | 自由に選んだ場と、各条件での発言機会 | 選択の構成比と条件別の応答 |
| 観察対象から見えなくなった参加者はどこにいるか | 以前の観察名簿、資料ごとの識別子、収集範囲 | 参加の移動先、収集範囲の不明、集団構成の変化 |
| 選択肢が変わっても同じ人の行動が変わるか | 各人の選択機会、実際の選択、その記録の有無 | 同一人物で対応づけた変化の範囲 |
| 一回のやり取りで表現がどう動いたか | 順序と会話境界を保った発言 | 経路、変化点、単純な平滑化との比較 |
| ある発言に特定の働きがあったか | 話者・宛先・対象命題・観察打切り時点 | 根拠となる発言箇所と反証、判断保留の理由 |
| 二つの見方が何を共同で絞り込むか | 同じ対象・時点を測った二系列 | 共有成分の許容範囲と単純な比較との差 |

4W をデータ表にすると、where は参加機会と選択、what は実際の表現、who は参照集団からの偏り、when は順序や経過時間になる。特定の場所を繰り返し選ぶこと自体が個人差になりうるので、場所の平均を一律に差し引かない。

複数資料に同一の参照を適用するときは、[一括計分の形式・実測時間・CPU/GPU 比較](GRAIN_PIPELINE_PERFORMANCE.md)を参照。資料ごとの集計単位は変わらない。

## 2. 同じ文を並べ替えて、最初の研究を動かす

リポジトリのルートで Python 3.12 を使う。依存パッケージ導入後はオフラインで実行できる。入力は架空の英文で、言語モデル、個人データ、有償サービスはいずれも不要である。

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-lock-main.txt
python -m examples.handbook_study /tmp/grain-first-study
```

新しい出力先を指定する。[実行コード](../examples/handbook_study.py)は、経路を選ぶ課題の短文を生成する。開発用の12人の文章だけで語彙・射影・ノードと候補因子を学ぶ。別の10人で基準分布を作り、最後の2人に初めて適用する。二人は各場面で計画に関する文を3回、別案に関する文を3回ずつ使う。一人はまとめて述べ、もう一人は交互に述べる。文の作成に使った分類名は計算に渡さない。

| 手元にできるファイル | 確認すること |
|---|---|
| `discovery.json`、`native-reference.json` | 開発資料・切り方・ノード・条件・A/B 間の因子負荷が他の人を用いずに決まったか。 |
| `calibration-units.json`、`chart.json` | 二つの観測量は第一ノードの平均所属度と、会話内の隣接するノードベクトル間の平均距離。各会話で計算し、会話を等重みにして一人一行にしたか。 |
| `target-units.json`、`positions.json` | 実行例では所属度の百分位（0–1）はともに 0.15、平均移動距離では 0.40 と 1.00。後者の 1.00 は参照10人の全員より大きいという意味。 |
| `target-families.json` | 上の説明用に指定した二軸とは別に、開発資料から求めた各特徴族の得点と元の特徴を収録。採択した軸がない場合は `null`。 |

注目すべき点は数値そのものより、**発言の集合が同じなら静的構成は等しく、並びが違えば動きは異なりうる**ことにある。同じ参照図のまま位置づけだけを再実行するには次を使う。

```sh
python -m grain_core.liquid_reference_error locate --chart /tmp/grain-first-study/chart.json --input /tmp/grain-first-study/target-units.json --out /tmp/grain-first-study/recheck.json
```

## 3. 自分のコーパスを準備する

匿名の著者 ID、会話・発話 ID、話者・宛先、条件、課題形式、観測時刻と時間帯、編集版、判断時点で参照できた文脈を保存する。他人の引用と本人の表明を分ける。発言がなかったときは、機会がなかったのか、機会はあったが応じなかったのかを記録する。自由参加と割付条件も分ける。

```json
{"language":"en","clock":"opportunity","episodes":[
  {"id":"case-01","author":"p17","condition":"detour","carrier":"route-note",
   "view":"A","events":["I checked the route on paper.","I tried another route."]}]}
```

一件でも凍結済みの読み取り器に渡せる。これだけで集団の因子は学べない。対話では[二者用の形式](../examples/liquid_new_dialogue.json)を使う。まず開発・校正・新規適用の著者を分け、その後、同じ人の重ならない機会を A/B にする。別の相手にも通用すると言いたいなら相手も分ける。英語の原文入口は、残したスライス一つを一機会として数える。日本語原文、既に得点化した日本語系列、英語常模を使った日英比較は別の作業である。日本語に移す際は言い換え・否定・引用への反応、未登録語、共通の基準資料を点検する。

**手元の資料に置き換える。** 上の形式で `discovery.json`、`calibration.json`、`target.json` を同じ非公開ディレクトリに置き、`python -m examples.handbook_study /tmp/grain-my-study --inputs /path/to/prepared` を実行する。著者 ID は共通の体系とし三群間で重複させない。この移動距離の例では各エピソードに2件以上、校正人数は軸数より多く、校正時に両軸にばらつきが必要である。校正・適用時に全語が辞書外の発言があれば処理を止める。出力先には原文のコピーも作られるため、公開しない。実時間や既存尺度の軸は専用の数値入口から扱う。

`calibration.json` の最上位には `population`（参照集団の定義）と `namespace`（三群で共通の著者 ID の体系）も指定する。後日、新規の発言資料だけが届いたときは `native-reference.json` と `chart.json` の二ファイルを保管しておけばよい。次の操作は語彙、負荷量、参照分布のいずれも再推定しない。

```sh
python -m examples.handbook_study /tmp/grain-placed --frozen-from /tmp/grain-first-study --new /tmp/grain-first-study/target.json
```

## 4. 原文からノード、因子、残差へ

まず発言全体で測り、発言内の変化を知りたい場合に短い窓を加える。長さをそろえる固定幅、開発資料で境界を学ぶ意味的分割、既存の条件語彙を使う分割では、同じ「第3軸」に異なる意味がある。比較には同一の未使用資料を両方で読む。原生の英語入口は TF–IDF、切り詰め SVD、標準化を経て木の葉または混合分布への所属度を与える。辞書外は `outside_vocabulary` として残す。一単語が辞書にあるだけでは意味の違いまで読み取れたとは言えない。

ノードは局所表現の住所、因子は複数の人・観測機会をまたいで再現する特徴の組合せである。あるノードを説明するには、典型例だけでなく境界例と同話題の反例を読む。元の研究を再現する場合は[制作記録 S1–S10](WORKED_EXAMPLE_MANUAL.md)の参加者分割、切片化、模擬データでの点検、別機会での再検査、選択の評価、候補発見、盲検評定と外的関連の順に従う。[登録済みの構成概念](CONSTRUCT_REGISTRY.md)と、新規コーパス上の番号だけの軸は区別する。

ノード所属度を $p_t$ とすると、その平均は水準、各条件に入った割合は選択、条件内平均と本人の全体平均との差は条件反応を表す。観測がない条件の差は未定義。動的特徴では変動性、慣性、粗さ、傾向、変化点、多尺度の記述を扱い、別の会話をまたぐ差を作らない。この実装の `hybrid` は条件別偏差であり、旧研究の静的・動的な共通部分空間とは定義が異なる。因子が形成されず残差に類似性が見えても捨てず、長さ、話題、書き癖、条件反応のどれと連動するかを調べる。Big Five や MBTI は別人で外的関連を調べるための基準である。

## 5. 参照と誤差を伴う個人得点

百分位は「対象より小さい参照値の割合＋同値の割合の半分」。白色化後の中心からの距離は非典型さを示し、偏りの向きまでは示さない。元の符号付き各軸を一緒に読む。同じ人を経時比較するなら参照を固定し、文量と出現機会の変化を添える。`legacy_batch_relative_node_scores` はその都度のバッチ内での比較用であり、不変な個人得点として転記しない。

人を取り替えたときの不確かさは人単位、場面を取り替えたときの不確かさは会話単位で評価する。未観測条件のために複数の値があり得ることと、標本の少なさによる信頼区間は別々に書く。参照を変更した場合は共通資料で再校正するか、別の単位として併記する。

## 6. 液態経路で拡散・粘度・撤回を読む

オプションの実行環境には PyTorch と ncps（確認版 1.0.1）が必要。新しい観測者には、既に凍結した参照だけを適用する。

```sh
python -m grain_core.liquid_instrument fit --input /tmp/grain-first-study/discovery.json --out /tmp/grain-first-study/ltc.json
python -m grain_core.liquid_instrument score --reference /tmp/grain-first-study/ltc.json --input examples/liquid_new_episode.json --out /tmp/grain-first-study/episode-scores.json
python -m grain_core.liquid_dialogue --reference /tmp/grain-first-study/ltc.json --input examples/liquid_new_dialogue.json --out /tmp/grain-first-study/dialogue-scores.json
```

`native` は現在の所属度、`fixed_half` は一定の保持率による平滑化、`liquid` は次ノードの学習分布、`anchored_signed` は一回ごとにリセットした場合に対する符号付きの履歴修正である。四つを同種の確率として比較しない。先行スライス k を空にしても機会時計を進め、時点 t の読みの差を測るのが `missing_effect[k][t]`。全体を空にした効果と個別効果の和の差は `joint_minus_sum`、両端を固定し中間の順番を交換したときの差は `same_ends_middle_swap_rms`。一エピソードの上限は128スライスである。

粘度の比較では話題・長さ・表現機会をそろえ、同じ手掛かりがまずどれだけ書き込まれ、その後どの位置まで残るかを見る。全員に同じ文を書かせれば、漂いだけでなく個人差も消える。撤回は「基準→情報追加→撤回」とし、実際の共通接頭部分をもつ別の展開と比べる。基準への距離と回復率を併記し、初期変位ゼロなら率は出さない。順序を逆にする操作とは分ける。実時間の間隔には `liquid_event_time`、入力を一定とみなす区間の厳密な連続時間発展には [Riccati モデル](GRAIN_RICCATI_AND_INTERPERSONAL_UPDATE.md)を使う。[数値入力・過去の因子バンク・逆問題の仕様](GRAIN_LIQUID_TOOL.md)も参照されたい。

## 7. 発話の機能と二人の関係

```sh
python -m grain_core.event_response examples/event_response.json
```

この例で相手が red を blue に訂正し、本人が次の発話で blue を使うと答える。「新しい前提を採用した」という命題の根拠は訂正そのものではなく本人の応答である。後の行動は別に記録する。支持・反証・返答はあるが判断できない・まだ返答を観測していない、を混ぜない。全体の重みの 0.75 を占める層で全例支持、残り未観測なら全体の支持割合の範囲は [0.75,1]。明示的な英語表現の規則が届かない発言には、独立に符号化し出典を紐付けた証拠を用いる。

共同経路と本人だけの経路は、同じ発言・切片で対応づける。後者では相手の発言内容だけでなく一つの機会も取り去られる。相手からの寄与を調べるには同じ共同時計上で本人または相手の過去入力を順に空にする。また「相手を理解できた」という本人の評価は、相手が本人に付けた性格評定ではない。評定の向きを記録する。

### 自由投稿・独立した作文・課題ログを扱う

```sh
python -m examples.evidence_panel examples/evidence_stream_demo.jsonl /tmp/grain-observed.json \
  --queries examples/evidence_stream_queries.json
```

`diagnostics` で収集範囲と有効な測定数を確認し、`forum_flow`、`writing_shift`、`paired_choice` の順に読む。記録がないことは明示的な拒否ではない。固定語彙で数値化できない文章も、参加の記録として残る。例では、選択結果が不明な機会を埋めず、同じ人の選択率の変化を `[0.5, 1.0]` として出す。異なる資料の同じ番号を、そのまま同一人物とみなさない。[観測パネルの入力仕様と実行例](GRAIN_EVIDENCE_PANEL.md)。

指定した行動の条件別頻度には `response_profile` を使う。`measure_calibrated` は独立に校正した読者がある場合だけ用い、元の結果と補正結果を別々に残す。返答の誤分類と返答を観測していないことは分け、校正範囲と観測値が両立しなければ点を推定しない。[校正と比較可能性の手引き](GRAIN_PSYCHOMETRIC_OPEN_STREAM_V2.md)。

## 8. 二視点の共通部分とベクトル経路

二つの量表場が同じ発話に反応しても、共有成分、同方向に動いた固有成分、共通の読者の癖が考えられる。`liquid_common_range` は校正された視点と明示的な固有成分の許容幅から、共存し得る状態を返す。唯一の共有軸を仮定して逆算する道具ではない。

```sh
python -m grain_core.dual_view_increment examples/dual_view_increment.json
```

各視点の履歴を個別に伝播して交差させた区間は [−0.4,2.0]、同じ履歴状態を要求した区間は [0.8,1.2]。後者だけがゼロを除く。すでに簡単な履歴比較で同じ判断になる場合には、簡単な方法を残す。[詳細な出力表](GRAIN_EVENT_AND_VIEW_INCREMENT_JA.md)。特定の人格語を質問したときの手掛かりを調べるには、原文・読者・質問・介入の対応を保つ。ここでの事象削除は、神経回路の一部を実際に置き換えたことを意味しない。[機構研究の補論](paper/GRAIN_MECHANISM_SUPPLEMENT_JA_V1.md)はその区別を扱う。

## 9. 新しい場面に対する量具の制作

1. 「訂正後に本人が案を改めたか」のように対象を限定し、対象集団、観察期限、機会の分母、支持例と反例を書く。
2. 自由に選んだ場面と、全員に同じ表現機会を与えた場面を別々に集める。同じ話の再掲は独立項目にしない。
3. 誰から誰への働きかけかを原文に結び付ける。同話題の反例、違う言い回しの支持例を独立評定者に示す。
4. 開発用の人で切り方・証拠規則・座標を決め、別の人で閾値や参照を校正して凍結する。LLM で説明文を作るときも証拠と説明を別欄にする。
5. 新規対象には再学習せず適用し、同じ時点・機会で単純な支持率、語彙ベースの結果、読者の直接判断と比較する。心理的な構成概念として命名するなら、独立の行動や外的基準との関連を添える。
6. 分母・不明・反証・誤差を含む結果、参照、適用できない場合を別チームに渡し、凍結版で再現してもらう。[B1–B7 制作手順](GRAIN_CONTEXTUAL_CONSTRUCTION_HANDBOOK_V1.md)、[校正済みバンドルの利用](GRAIN_F16_PUBLIC_CALIBRATED_BUNDLE_HANDBOOK_V1.md)。

## 過去の研究を、今日の道具選びに生かす

[構成概念登録簿](CONSTRUCT_REGISTRY.md)では、一人称使用や指示的な文体と、主に発言場所の選択を映すと再分類された新奇性・遊びの語彙、スライス水準の揺らぎにとどまった負の感情語率を区別する。V6 は水準・条件別の傾き・運動を区別し、V7 は切り方・参照・誤差を座標に結び付け、V8 は個人ベクトル、二者関係、集団の場を別の対象として扱う。ある二人の話し方が近いことから、第三者の個人得点は出ない。数値化済みの符号付き系列は `liquid_axis_series` で元の軸順・座標を保ち、校正期間より後に適用する。過去の V7 座標を `liquid_frozen_bank` で再現するには元の凍結バンクが要る。

RealPersonaChat の理解度は回答者自身が相手をどの程度理解できたか、積極性は自己評定である。ESConv で援助方略間の差が観察されたことと、相談者の苦痛が軽減したことは別の結果だった。援助者の行為と相談者の状態は別々の欄に書く。絵を使った物語課題では文順を入れ替えて叙述の流れを検討できる。潜在課題では試行の実時間を扱える。共通なのは問いの立て方で、両者の得点が一つの集団基準になるわけではない。既に数値のある試行系列には `liquid_task_paths` を用いる。[各コホートの根拠と対照結果](paper/GRAIN_LIQUID_RICCATI_EVIDENCE_PROVENANCE.md)。

## 10. 適用、トラブルと報告

推薦に用いるなら近い資料と「どの場面・表現が近かったか」を返し、話題の類似だけの場合と比較する。市場の全文プールと選別プールでは一日・一銘柄を単位とし、情報締切・市場暦・重複を明示する。共同状態が正であることと翌日寄付きが上昇することは別の検証を要する。面接記録では当該場面での観察と別の読み方を研究者に返し、個人の原文を公開しない。長い投稿と一回の短い応答を同じ時間単位として扱わない。

| 症状 | 確認すること | 扱い |
|---|---|---|
| 異なる文が同じ経路になる | 入力語彙、否定・引用の置換、最初に差が消える層 | 時間モデルを変える前に入口を点検する。 |
